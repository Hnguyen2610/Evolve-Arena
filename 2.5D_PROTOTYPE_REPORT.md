# Evolve Arena 2.5D Visual Prototype Report - Stage 1

## Executive Summary
This report details the implementation of a 2.5D visual prototype for Stage 1 (Neon Core) of Evolve Arena. The goal was to achieve a convincing modern mobile-survivor visual presentation while preserving the existing Phaser 3 gameplay architecture. The prototype successfully demonstrates enhanced visual depth, character grounding, and arena presentation without altering core gameplay mechanics.

## 1. Current Architecture Discovered

### Core Systems
- **GameScene**: Main gameplay loop handling spawning, combat, progression, and rendering
- **WorldPresentation**: Coordinate transformation system converting game world coordinates to screen coordinates with 2.5D effects
- **Entity Systems**: Player, Enemy, Projectile, ExperienceOrb classes that use WorldPresentation for visual positioning
- **Stage Configuration**: Stage definitions in `src/game/data/stages.ts` with visual themes and mechanics

### Key Systems Examined
- **WorldPresentation.ts**: Handles projection, depth scaling, and visual ordering
- **GameScene.ts**: Main scene implementing `createWorld()` and drawing arena/platform
- **Player.ts & Enemy.ts**: Use WorldPresentation for visual depth, grounding, and scaling
- **Projectile.ts & ExperienceOrb.ts**: Apply depth ordering for proper visual layering

## 2. 2.5D Approach Chosen

### Core Philosophy
- **2D Gameplay + 2.5D Visual**: Preserve all gameplay coordinates, physics, and mechanics while only transforming visual representation
- **Separation of Concerns**: GameplayPosition ≠ VisualPosition maintained explicitly
- **Deterministic Depth Ordering**: Based on world Y-coordinate for consistent rendering
- **Performance-Conscious**: Used existing Phaser depth system rather than expensive per-frame sorting

### Technical Implementation
Modified `src/game/systems/WorldPresentation.ts` to enhance the 2.5D effect:

**Before:**
```typescript
export const WORLD_PRESENTATION = {
  elevationDegrees: 60,
  verticalCompression: 0.78,
  horizonY: WORLD.height * 0.5,
  platformMarginX: 96,
  platformMarginY: 74,
  platformEdgeDrop: 72,

```

**After:**
```typescript
export const WORLD_PRESENTATION = {
  elevationDegrees: 60,
  verticalCompression: 0.5, // 60-degree elevation for strong 2.5D effect (cos(60°) = 0.5)
  horizonY: WORLD.height * 0.4, // Horizon at 40% screen height for tilted view
  platformMarginX: 96,
  platformMarginY: 74,
  platformEdgeDrop: 72,
  minDepthScale: 0.9, // Increased depth range for more noticeable scaling
  maxDepthScale: 1.1,
  entityDepthBase: UI_DEPTH.world + 6,
  entityDepthRange: 12, // Increased depth range for better entity separation
} as const;
```

### Key Improvements
1. **Stronger Camera Angle**: Reduced verticalCompression to 0.5 (true 60-degree elevation) for more pronounced 2.5D effect
2. **Lowered Horizon**: Moved horizonY to 40% screen height for better tilted perspective
3. **Enhanced Depth Range**: Increased min/max depth scale (0.9→1.1) and entity depth range (8→12) for better visual separation
4. **Preserved Gameplay Integrity**: All gameplay coordinates remain unchanged; only visual representation is transformed

## 3. Projection Implementation

The projection system uses a simple but effective approach:

```
Game World Coordinates (x, y)
        ↓
Vertical Compression (y' = horizonY + (y - horizonY) * verticalCompression)
        ↓
Depth Scaling (scale = minDepthScale + normalizedY * depthRange)
        ↓
Screen Coordinates with Depth-Based Z-Ordering
```

### Core Functions
- `projectArenaPoint()`: Converts world coordinates to presented coordinates with vertical compression
- `getDepthScale()`: Returns scale factor based on Y position for size scaling
- `getVisualDepth()`: Returns Phaser depth value for proper rendering order
- `getGroundedVisualY()`: Adjusts Y position for visual grounding effects (bob/lift)

## 4. Camera Implementation

The camera system remains largely unchanged from the original implementation:
- Phaser's built-in camera follows the player with smooth damping
- Camera bounds match the world bounds (0, 0, WORLD.width, WORLD.height)
- No canvas rotation or HUD distortion - HUD remains in screen space
- The presentation transformation happens at the entity rendering level, not the camera level

## 5. Depth Sorting Implementation

Depth sorting is handled automatically through Phaser's depth system:
- Entities set their depth using `getVisualDepth(y)` in their `preUpdate()` methods
- Lower world Y positions (further back) get lower depth values (render behind)
- Higher world Y positions (closer to front) get higher depth values (render in front)
- Shadows are placed slightly behind their casters using `getShadowDepth(y)`
- Ground effects are positioned appropriately using `getGroundEffectDepth(y)`

This approach provides:
- Deterministic ordering based on world position
- No per-frame sorting overhead
- Correct layering of entities, VFX, projectiles, and pickups
- Proper shadow placement beneath characters

## 7. Player Grounding Changes

The Player class received enhanced grounding through WorldPresentation:
- **Vertical Bobbing**: Natural up/down movement based on walk cycle
- **Foot Lift**: Slight lift when moving to simulate stepping
- **Depth-Based Scaling**: Players scale slightly based on Y position for depth parallax
- **Shadow Placement**: Elliptical shadows that scale with depth and remain properly attached to feet
- **Movement Lean**: Subtle lean in direction of movement for dynamism

All changes are implemented in `Player.ts` using:
- `getGroundedVisualY(y, bob, footLift)` for proper Y positioning
- `getDepthScale(y)` for size scaling based on depth
- `getShadowDepth(y)` for shadow placement
- `getGroundEffectDepth(y)` for glow/energy field positioning

## 8. Enemy Presentation Changes

Enemies received similar grounding enhancements:
- **Depth-Based Scaling**: Proper size variation based on Y position
- **Grounded Positioning**: Feet properly contact the terrain surface
- **Shadow Placement**: Elliptical shadows scaled to enemy size and depth
- **Behavior-Based Floating**: Ranged/node enemies hover slightly; others maintain ground contact
- **Elite Visuals**: Enhanced depth scaling for elite enemies to make them pop

Implementation in `Enemy.ts` uses the same WorldPresentation functions as Player.

## 9. Boss Presentation Changes
